# 실거주 아파트 찾기 도구

서울과 **서울 접근성이 좋은 경기 지역**에서 조건(매매 3~7억 · 전용 59㎡+ · 300세대+ ·
서울 도심 45분 이내(지하철·자차 중 빠른 쪽) · 주상복합 제외)에 맞는 아파트 단지를 공공데이터로
자동 추출하고, 세대수·학군·병원·마트·전통시장까지 한 화면에서 비교하는 도구입니다.

**대표가격은 "단지 × 면적대"별 중앙값입니다.** 같은 단지라도 34㎡와 84㎡는
전혀 다른 물건이므로 절대 한 통에 섞지 않습니다.

## 공개 대시보드

`docs/index.html`이 GitHub Pages로 서비스됩니다 → **https://jihoonhappy.github.io/house/**

이 페이지는 저장소 소유자의 조건으로 돌린 **결과 스냅샷**입니다. `03_dashboard.py`를

## 1. 준비 — API 키 발급 (모두 무료)

1. **공공데이터포털** https://www.data.go.kr — 회원가입 후 활용신청
   - [아파트 매매 실거래가 자료](https://www.data.go.kr/data/15126469/openapi.do)
   - 마이페이지의 인증키를 사용. **Encoding/Decoding 어느 쪽을 넣어도 동작합니다.**
2. **서울 열린데이터광장** https://data.seoul.go.kr — 인증키 (지하철역 좌표)
3. **나이스 교육정보 개방포털** https://open.neis.go.kr — 인증키 (학교 위치)
4. **카카오 개발자** https://developers.kakao.com — 앱 생성 후 REST API 키
   - ⚠️ 키 발급만으로는 부족합니다. **내 애플리케이션 → 제품 설정 → 카카오맵 → 활성화 ON**
     을 반드시 켜세요. 꺼져 있으면 `disabled OPEN_MAP_AND_LOCAL service` 403이 납니다.
   - 로컬 API 한도는 **일 30,000건**입니다. 이 도구의 1회 전체 실행은 약 2,400건을 쓰며
     (초등학교 610곳 + 후보 단지, 각 최대 2회) 결과는 `data/geocode_cache.json`에
     캐시되어 재실행 시 거의 호출하지 않습니다. 조건을 크게 넓히면 호출이 늘어나므로
     `config.yaml`의 `api_limits.kakao_daily_call_budget`(기본 25,000)이 예산을 넘기 전에
     캐시를 저장하고 중단시킵니다. 다음 날 다시 실행하면 남은 것부터 이어서 처리합니다.

5. **한국부동산원 단지 식별정보** — 수도권분은 `bundled/`에 동봉돼 있어 **추가 작업이
   없습니다.** 수도권 밖으로 넓히려면
   [기본정보 (15106861)](https://www.data.go.kr/data/15106861/fileData.do)에서 원본 CSV를
   받아 프로젝트 폴더에 두세요(활용신청 불필요, 파일명 그대로 두면 자동 탐색).
   자세한 내용은 `bundled/SOURCE.md`.

```bash
cp config.example.yaml config.yaml   # 그 뒤 키 4개를 채워 넣기
```

키를 파일에 두기 싫다면 환경변수가 우선합니다:

```bash
export APT_DATA_GO_KR=...  APT_SEOUL_OPEN_DATA=...  APT_NEIS=...  APT_KAKAO_REST=...
```

## 2. 실행

```bash
pip3 install pyyaml        # 유일한 실행 의존성
python3 01_collect.py      # 최초 10~20분 (25개 구 × 12개월 + 초등학교 지오코딩)
python3 02_analyze.py
python3 03_dashboard.py
open dashboard.html
```

- 수집 결과는 `data/`에 캐시됩니다. 중간에 끊겨도 다시 실행하면 **못 받은 구/월만** 받습니다.
- 매달 실거래가 갱신되므로 월 1회 `01_collect.py`부터 다시 돌리면 새 후보가 들어옵니다.
- 조건 변경은 `config.yaml`만 고치면 됩니다.

## 점수 체계

100점 만점을 10개 항목으로 나누고, 성격별로 4개 그룹에 묶어 함께 보여줍니다.
**그룹 점수를 모두 더하면 총점과 같습니다.**

| 그룹 | 배점 | 포함 항목 |
|---|---:|---|
| 교통 | 30 | 서울 접근성 18 · 역까지 거리 12 |
| 단지 | 28 | 세대수 10 · 거래 활발도 10 · 준공년도 8 |
| 학군 | 22 | 학군(중·고·학원가) 12 · 초등학교 거리 10 |
| 생활인프라 | 20 | 병원 8 · 대형마트 7 · 전통시장 5 |

각 항목은 0~1로 정규화한 뒤 배점을 곱합니다. 만점 조건은 `config.yaml`에서 정합니다
(예: 역까지 0m면 만점, `station_max_distance_m` 이상이면 0점).
그룹 구성은 `score_groups`에서 바꿀 수 있고, **모든 배점 항목이 정확히 한 그룹에만
들어가야** 설정 검증을 통과합니다(그래야 그룹 합이 총점과 같아집니다).

## 가격 이력

대표가는 **최근 6개월** 시세지만, 그 값이 비싼지 싼지는 이력 없이 알 수 없습니다.
그래서 같은 실거래 데이터를 84개월(7년)치까지 받아 함께 보여줍니다.

| 컬럼 | 뜻 |
|---|---|
| 7년평균비 | 7년 전체 거래 평균가와 대표가의 차이 (%) |
| 전고점비 | 반기 중앙값 최고점 대비 대표가의 위치 (%) |
| 추이 | 반기 중앙값 꺾은선 (오르면 빨강, 내리면 파랑) |

원본 7년치는 약 137만 건·280MB라 통째로 저장하지 않습니다. 수집 캐시를 한 달씩
읽어 **"단지 × 면적대 × 반기 중앙값"으로 접어서** `data/price_history.json`(수백 KB)에
저장합니다. 반기로 묶는 이유는 단지·면적대 단위로 쪼개면 분기당 거래가 0~2건뿐이라
중앙값이 흔들리기 때문입니다.

## 3. 조건 바꾸기 (config.yaml)

| 항목 | 뜻 |
|---|---|
| `price_min` / `price_max` | 대표가격 범위 (만원) |
| `area_min_m2` / `area_max_m2` | 전용면적 하한/상한 (0 = 제한 없음) |
| `area_bands` | 면적대 구간 정의. 구간이 다르면 별도 후보로 집계 |
| `lookback_months` | 후보 선정용 실거래 수집 기간 |
| `history_months` | 가격 이력 기간 (84 = 7년) |
| `price_window_months` | 대표가격에 쓸 최근 창. 이 안에 거래가 부족하면 전체 기간으로 자동 폴백 |
| `min_trade_count` | 대표가격을 믿기 위한 최소 거래건수 (1건짜리 특이거래 배제) |
| `station_max_distance_m` | 역세권 판정 거리 (필터) |
| `school_max_distance_m` / `school_filter` | 초등학교 거리. `school_filter: true`면 필터로도 작동 |
| `scoring` | 점수 가중치 (합계 100 권장) |
| `score_groups` | 점수 그룹 구성. 모든 항목이 한 그룹에만 속해야 합니다 |
| `min_households` | 세대수 하한 (0 = 제한 없음) |
| `exclude_complex_types` | 제외할 단지분류. 부분 일치 (`"주상복합"`이 `"도시형 생활주택(주상복합)"`도 걸러냄) |
| `require_complex_match` | true면 공공 단지정보에 매칭된 단지만 남깁니다 |
| `amenities` | 편의시설 반경검색 정의. `contains`로 검색어 오탐을 걸러냅니다 |
| `school_zone` | 학군 산정 반경과 만점 기준 |
| `reb_csv` | 단지 식별정보 CSV 경로 (비우면 자동 탐색) |
| `publish_to` | 공개용 사본 경로. `""`면 만들지 않습니다 |
| `max_commute_min` | 서울 도심까지 추정 소요시간 상한 (분, 0 = 제한 없음) |
| `require_station` | 역세권을 통과 조건으로 쓸지. false면 통근시간만으로 거릅니다 |
| `station_walk_max_m` | 이보다 역이 멀면 지하철을 선택지에서 뺍니다 |
| `walk_speed_kmh` | 역까지 도보 속도. 지하철 시간에 도보 시간을 더합니다 |
| `access.destinations` | 접근성 기준 거점역 (기본 강남·시청·여의도) |
| `access.driving` | 자차 소요시간도 조회해 빠른 쪽으로 판정할지 |
| `access.driving_departure_hour` | 자차 조회 기준 시각 (다음 평일 이 시각) |
| `api_limits.kakao_driving_call_budget` | 자차 길찾기 호출 상한 (한도 일 5,000) |
| `transit` | 노선별 표정속도·환승/대기 시간 등 소요시간 추정 상수 |
| `school_office_codes` | 나이스 시도교육청 코드 (B10 서울, J10 경기, E10 인천) |
| `seoul_districts` / `gyeonggi_districts` | 조회할 시군구. 줄을 지우면 건너뜁니다 |
| `api_limits.kakao_daily_call_budget` | 카카오 지오코딩 일일 호출 상한 (한도 30,000 대비 여유분) |

## 한계 (알고 쓰기)

- **실거래가 ≠ 현재 호가.** 이 도구는 "이미 거래된 가격"으로 후보를 압축합니다.
  실제 매물·호가는 대시보드의 네이버/호갱노노 링크로 직접 확인하세요.
  (매물 정보는 공식 API가 없고 크롤링은 약관상 제약이 있습니다.)
- 역·학교 거리는 **직선거리**입니다. 실제 도보 거리는 더 깁니다.
- **학군은 학업성취도가 아닙니다.** 학업성취도·진학률 공개가 중단되어 공식 API가 없어,
  중·고 접근성과 학원가 밀집도(카카오 학원 카테고리)로 근사합니다. 참고 지표로만 쓰세요.
- **주상복합 판별은 매칭된 단지에 한합니다.** 서울시 공동주택 정보는 의무관리대상
  2,885개 단지만 담고 있어, 소규모·신축 단지는 분류를 알 수 없습니다.
  `require_complex_match: true`면 이런 단지는 후보에서 빠집니다.
- 병원 수에는 의원·치과가 모두 포함됩니다. 종합병원은 별도 항목으로 봅니다.
- **역세권은 통과 조건이 아닙니다.** 역이 먼 택지지구(범박·옥길 등)도 자차로 다닐 수
  있으면 후보에 남습니다. 대신 **지하철 시간에 역까지 도보 시간을 더해** 자차와 공정하게
  비교합니다(자차는 집 앞에서 재므로). 역이 `station_walk_max_m`보다 멀면 지하철은
  선택지에서 빠지고 자차만 봅니다.
- **자차 시간은 다음 평일 아침 기준 조회값입니다.** 실시간 조회는 실행 시각마다 값이
  달라 비교가 불가능해서, 항상 "다음 평일 오전 8시" 출발로 고정 조회합니다. 주차 여건과
  유류비는 반영되지 않으므로 도심 출퇴근에 실제로 차를 쓸지는 따로 판단하세요.
- **지하철 소요시간은 추정치입니다.** 노선 순서와 역 좌표로 만든 그래프에 노선별 표정속도를
  적용해 계산합니다. 급행·특급, 배차간격, 버스 환승을 반영하지 않아 실제보다 보수적이며
  참고 구간 16곳 기준 평균오차 약 6분, 1호선 장거리 구간은 최대 20분까지 벌어집니다.
  단지 간 우열을 가리는 용도로만 쓰고, 실제 통근은 지도 앱으로 확인하세요.
- **서울 밖 주상복합 판별에는 data.go.kr API 두 개가 필요합니다.**
  [단지 목록제공(15057332)](https://www.data.go.kr/data/15057332/openapi.do)으로 단지코드를
  열거하고, [기본 정보제공(15058453)](https://www.data.go.kr/data/15058453/openapi.do)으로
  그 코드의 분류를 조회합니다. 둘 다 활용신청이 필요합니다.
  목록이 없으면 그 단계는 경고만 남기고 건너뛰며, 해당 지역 단지는 "분류 미확인"으로
  남습니다(`require_type_known`은 분류 자료가 있는 지역에만 적용되므로 후보가
  통째로 사라지지는 않지만, 주상복합이 섞여 있을 수 있습니다).
- 이름이 비슷한 옆 단지를 잘못 짚지 않도록, 조회 결과의 **지번 주소가 후보와 맞는지
  확인한 뒤에만** 분류를 반영합니다.
- 해제(취소)된 거래는 제외하지만, 최근 거래는 신고 지연으로 누락될 수 있습니다.
- 지정 기간에 거래가 `min_trade_count` 미만인 단지는 후보에 나타나지 않습니다.
